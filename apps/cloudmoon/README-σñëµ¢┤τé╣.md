# CloudMoon サイト v5 — 速度優先チューニング

v4 で「最低ビットレートを 3.6 Mbps に固定」してしまったため、回線が混んだときに
輻輳制御が下げられず、通信が詰まって極端に遅くなる状態になっていました。
v5 では低遅延・低詰まりを最優先に組み直しています。

## v4 → v5 の変更

| 項目 | v4 | v5 |
|---|---|---|
| 最低ビットレート (`x-google-min-bitrate`) | 3600 kbps（**これが渋滞の原因**） | **300 kbps** — 回線が細れば即座に落とせる |
| 開始ビットレート | 7200 kbps | 回線に応じて 1000〜3500 kbps |
| ビットレート上限 | 12000〜20000 kbps 固定 | 回線判定で 3500 / 7000 / 14000 kbps |
| 解像度 | 高解像度端末は常に 1080x1920 | 回線判定。細い回線では 720x1280 |
| ジッタバッファ | 常に 0（ロス時に固まる） | 回線判定で 0 / 30ms / 60ms |
| STUN サーバー | 中国のサーバーが先頭（日本から遅い） | 近い STUN を先頭に。TURN は保持 |
| ICE 候補プール | 10 | 4（接続確立が速い） |
| API ホスト選定タイムアウト | 3000ms | **1200ms** |
| 起動時の先読み (`prefetch`) | ポータル+プレイ画面を先読み | **削除**（初回表示の帯域を奪っていた） |

## 回線の自動判定

起動時に `navigator.connection`（実効速度・RTT・データセーバー設定）を見て
3 段階から自動で選びます。既定の動作モードは **speed（速度優先）** で、
判定より 1 段安全側に倒します。

| 段階 | 解像度 | 上限 | 開始 | 品質 | ジッタバッファ |
|---|---|---|---|---|---|
| 0（細い / 3G / データセーバー / RTT>250ms） | 720x1280 | 3.5 Mbps | 1.0 Mbps | SD | 60ms |
| 1（普通） | 720x1280 | 7 Mbps | 2.0 Mbps | HD | 30ms |
| 2（4G相当かつ RTT≤80ms） | 1080x1920 | 14 Mbps | 3.5 Mbps | HD | 0ms |

## 手動で上書きする（localStorage）

| キー | 値 | 説明 |
|---|---|---|
| `cm_mode` | `speed`（既定） / `balanced` / `quality` | 自動判定を 1 段ずらす |
| `cm_quality` | `HD` / `SD` / `LD` / `ULD` | 配信品質を固定 |
| `cm_bitrate` | 1000〜60000（kbps） | ビットレート上限を固定 |

例：常に最速で使いたい場合
```
localStorage.setItem('cm_mode','speed');
localStorage.setItem('cm_quality','LD');
localStorage.setItem('cm_bitrate','2500');
```
画質を戻したい場合
```
localStorage.setItem('cm_mode','quality');
localStorage.removeItem('cm_bitrate');
```

## v4 から引き継いでいる改善

- SVG → foreignObject → iframe → srcdoc → fetch → document.write の多段ラッピングを解消
- ゲーム起動時はラッパー（.svg）を経由せず `play-260605.html` へ直接遷移
- iframe の sandbox に `allow-pointer-lock` を追加（マウスロック修正）
- 映像への毎フレーム CSS フィルタを削除、GPU レイヤーに固定
- API ホストへの `preconnect`、EdgeOne 用 `_headers`（画像は 1 年キャッシュ）

## v7 の修正（PC で画面が横倒しになる問題）

### 原因
ベンダー側の「自動回転」仕様です。スマホの縦画面いっぱいに縦向きストリームを
表示するため、`ビューポートが横長ならゲーム表示を 270 度回転させる` という
分岐が入っていました。

```
initParams.nenlyRotateScreen ? direction = (幅 > 高さ ? 横 : 縦) : direction = 1
```

PC は常に「幅 > 高さ」なので必ず回転が有効になり、さらに `rotateHandler` が
`isRotateScreen` を書き換えて Vue の watch を発火させ、もう一度 `direction` を
反転させていました。結果として画面が横倒しになります。

### 修正
入力デバイスを見て自動回転を切り替えるようにしました。

- `pointer: coarse`（タッチ主体の端末）→ 従来どおり自動回転あり
- マウス/トラックパッド（PC）→ **自動回転オフ**。縦向きストリームを
  画面中央に正立表示（レターボックス）します
- `rotateHandler` 内の `isRotateScreen` 書き換えも、自動回転オフ時は
  現在値を代入するだけにして watch が誤発火しないようにしました

サイドメニューの `Page Orientation ↻` は従来どおり手動で切り替えられます。

### 手動での上書き
ブラウザのコンソールで:

```
localStorage.setItem('cm_rotate','off');   // 常に正立（PC 既定）
localStorage.setItem('cm_rotate','on');    // 常に自動回転
localStorage.removeItem('cm_rotate');      // 端末で自動判定に戻す
```

## v8 の修正（映像が小さく右上に寄る問題）

### 原因 1（本命）— v4 で入れた GPU ヒントが回転を打ち消していた
v4 で描画を滑らかにするために追加した以下の CSS が原因でした。

```css
#remote-video { transform: translateZ(0); }   /* v4 で追加 */
```

映像の回転はクラス `.rotate { transform: rotate(90deg) }` で行われますが、
ID セレクタ（`#remote-video`）はクラスより優先度が高いため、**映像だけ回転が
効かなくなり**、入力用キャンバスだけが正しく回転した状態になっていました。
その結果、映像が横長のまま左上寄りに小さく描画されていました。

修正：`transform: translateZ(0)` を削除。GPU 合成のヒントは
`will-change: transform` と `backface-visibility: hidden` で維持しています。

### 原因 2 — 横向きゲームのときに PC で表示枠が小さくなる
v7 で PC の自動回転を切ったため、横向きゲーム（`rotation = 1`）でも縦向きの
表示枠（563 x 1001 相当）が使われ、その中に横長映像が入るので小さくなって
いました。

修正：`rotateHandler` で、PC の場合はゲーム自体の向きに合わせて表示枠を
選ぶようにしました。

- 横向きゲーム + 横長ウィンドウ → 横向き枠（画面いっぱい）
- 縦向きゲーム → 縦向き枠（正立・左右レターボックス）
- タッチ端末は従来どおりの挙動

### 追加した保険 — 映像と入力面の同期
入力用キャンバスの `width` / `height` / `transform` / `transform-origin` を
監視し、映像側に常に同じ値を反映する処理を入れました。今後ベンダー側の
計算がずれても、映像と操作位置がずれないようにしています。

### 実測（1920 x 1001 のウィンドウ）

| ゲームの向き | 映像の位置とサイズ | 入力面 |
|---|---|---|
| 横向き | (70, 0) 1780 x 1001 | 完全一致 |
| 縦向き | (679, 0) 563 x 1001 | 完全一致 |

## v10 の修正（一部の端末でログイン後に Play Now が反応しない問題）

### 原因 1（本命）— ストレージが使えない端末で情報が消えていた
ログイン用トークン (`cm_auth_token`) と起動情報 (`cm_launch_data`) は
`localStorage` にだけ保存していました。v6 で入れたフォールバックは
**その場限りのメモリ**だったため、`localStorage` が使えない端末では

- ログイン直後の `location.reload()` でトークンが消える → ログインしたはずなのに未ログイン扱い
- `play-260605.html` へ遷移した瞬間に `sid` が消える → 読み込み画面のまま止まる

という状態になっていました。`localStorage` が塞がれる条件は珍しくありません
（Safari のプライベートブラウズ、「サイト越えトラッキングを防ぐ」、Cookie の全ブロック、
アプリ内ブラウザ、埋め込み表示など）。

修正：フォールバックを多段化しました。

`localStorage` → `sessionStorage` → Cookie → `window.name` → メモリ

Cookie と `window.name` はページ遷移・再読み込みをまたいで残るため、
全ストレージが塞がれている端末でもログイン状態と起動情報が保持されます。
現在どの層で動いているかは `window.__cmStorageMode` で確認できます。

### 原因 2 — 起動情報の受け渡しがストレージ頼りで、有効期限も 20 秒だった
`launchGameAction` は `sid` をストレージに書いてから遷移するだけで、
プレイ画面側の読み取り期限は **20 秒** でした。回線が細い端末では
ページの読み込み中に期限切れになることもありました。

修正：

- 遷移先を `./play-260605.html?sid=...&quality=...` に変更（URL で直接受け渡し）
- プレイ画面は `クエリ → URL ハッシュ → ストレージ` の順で `sid` を探す
- ストレージ経由の有効期限を 20 秒 → **10 分** に延長
- 復元した `sid` を `history.replaceState` で URL に書き戻すので、再読み込みでも復帰できる

### 原因 3 — 失敗時の戻り先 `main.svg` が存在せず 404 だった
セッション取得に失敗したときやゲーム終了時、ベンダー側のコードは
`./main.svg` へ戻ろうとしますが、この配布物には該当ファイルがなく
**404 の白画面**になっていました（「押しても何も起きない」と見える原因の一つ）。

修正：`main.svg` を追加し、ポータル (`index.html`) にリダイレクトします。
`play-260605.svg` も含めて、拡張子どおりの正規 SVG（スクリプト付き）に書き直したので
`image/svg+xml` として配信されても正しく動作します。

### 原因 4 — 残り時間の取得が終わる前に押すと「No time left.」で弾かれた
`handlePlay` は `timeLeft` が空のときも「残り時間なし」として扱っていました。
起動直後や通信が遅い端末では、実際には残り時間があるのに弾かれます。

修正：`timeLeft` が未取得の場合は残り時間をもう一度取得してから判定します。
取得そのものに失敗したときは、原因が分かる日本語のメッセージを出します。

### `sid` がどうしても受け渡せなかった場合
読み込み画面で止まらないよう、案内とポータルへ戻るボタンを表示します。

### あわせて行った安全側の調整（v10）
- フォールバックで使う `window.name` はタブ内で他サイトにも引き継がれるため、
  保存内容に有効期限（15 分）を付け、期限切れなら消去するようにしました。
- フォールバックの Cookie の保持期間を 30 日 → 7 日に短縮しました。
- `_headers` の `Referrer-Policy` を `strict-origin-when-cross-origin` に変更し、
  `sid` を含む URL が外部（CDN や API）へ Referer として送られないようにしました。
